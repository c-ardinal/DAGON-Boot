## ブラウザで

[DAGON Console のデモ](~/demo/)は、ブラウザの中で動きます。相手は模擬の親機 1 つと子機 2 つです。

1. 見本から構成を作ります。
2. 「書込」に切り替えて「接続する」を押します。
3. 「書き込む」を押すと、用意してある新しいバージョンをノードへ書き込みます。

デモはファイルを読み書きせず、機器につながず、鍵を持ちません。これらの操作は、指すと理由を表示します。

## dagon コマンドで

先に `dagon` コマンドを[入れます](/getting-started/install/)。

### `dagon demo`

```sh
dagon demo                         # 模擬のノードで DAGON Console を開く
dagon demo --sim-fail watch        # 同じで、watch への書き込みが失敗して元に戻る
dagon demo --sim-speed 4           # 4 倍の速さで動かす
```

`dagon demo` は DAGON Console を開きます。相手は模擬の親機と子機の 3 つのノードです（見本の構成: hub、seg、watch、すべて 1.0.0）。`dagon sim run` と同じシミュレータを、実機と同じ dagon-host のコードで動かします。

- つないで新しいバージョン（demo-1.1.0）を選ぶと、3 つのノードすべてに書き込めます。進み具合も見られます。
- `--sim-fail seg` か `--sim-fail watch` を付けると、その子機の新しいバージョンが起動時に落ち、1.0.0 に戻ります。
- リンクとフラッシュには実機に近い時間がかかります。`--sim-speed` で 0.1〜20 倍にできます。
- ヘッダには常に「模擬」が出ます。

デモは一時フォルダに自分のプロジェクト（`dagon-demo-<ユーザー名のハッシュ>`）を作ります。起動のたびに新しく作ります。デモ専用の DEMO の鍵も作ります。あなたの鍵は使いません。デモで署名したものは実機では動きません。

### `dagon sim run`

```sh
dagon sim run
```

シミュレータ上で、通しのシナリオを実行します。

- 転送中に電断が起きる書き込み
- 確定しないイメージ
- 改ざんしたパッケージ
- 全消去した F401 の、ROM ブートローダ経由の復活
