---
title: "ノード間のバージョンの整合"
description: "ノード間で必要なバージョンの関係を宣言する方法と、1台のノードが旧バージョンに残留した場合のDAGONの動作です。"
---

相互に通信するノードは、多数の場合、対応するバージョンの組合せを必要とします。
`topology.yaml`の`constraints`でその関係を宣言すると、DAGONはパッケージの作成時と、書込がノードで停止した時点の2箇所で関係を維持します。

## 制約の宣言

```yaml nocheck
constraints:
  - lockstep: [hub, seg]
  - requires: { node: seg, needs: hub, min: 1.2.0 }
  - min_bootcore: { node: seg, min: 1.0.0 }
```

| 制約 | 意味 |
|---|---|
| `lockstep: [ids]` | 列挙したノードは、同一パッケージのバージョンで同時に動作します。 |
| `requires: { node, needs, min }` | `node`は、`needs`のバージョン`min`以降を必要とします。 |
| `min_bootcore: { node, min }` | `node`は、ブートローダのバージョン`min`以降を必要とします。 |

構成に存在しないノードを指定した制約は拒否します（V-15）。

## パッケージの作成時

`dagon deploy`はパッケージ内のイメージで制約を検査し（RB-05）、制約に違反するパッケージを作成しません。
制約はパッケージの署名付マニフェストに格納します。書込時の判定は、PC上のファイルではなくパッケージの内容を使用します。

## 書込がノードで停止した場合

`dagon deploy`はノードを1台ずつ書込し、各ノードが新バージョンを確定した後に後続のノードを開始します。
ノードが失敗すると、後続のノードは開始しません。
失敗したノードは、書込前のバージョンで動作を継続するか、そのバージョンへ復帰します。

その後、DAGONは各ノードが動作中のバージョンで制約を判定します。

- `lockstep`: 列挙したノードの1台がパッケージのバージョン以外で動作中の場合、今回の書込で移行した列挙ノードは全て書込前のバージョンへ復帰します。
- `requires`: `needs`が`min`未満の場合、`node`は書込前のバージョンへ復帰します。必要とされる側のノードは新バージョンを維持します。
- 復帰したノードが他ノードの制約を破る場合、そのノードも復帰します。全制約が成立するまで反復します。
- 失敗したノードと制約で関係しないノードは、新バージョンを維持します。

ノードの復帰は`dagon rollback`と同一の方法です。別スロットのバージョンを起動して確定します。
各ノードの結果で経過を確認可能です。

| 結果 | 意味 |
|---|---|
| `done, <version>` | 新バージョンで動作し、確定済です。 |
| `back on <version>` | 書込と確定の後、制約の維持を目的に復帰しました。 |
| `on <version>, against a compatibility constraint ...` | 制約が不成立で、ノードは復帰不能でした。スロットが1つ、別スロットに有効なイメージが不在、今回の書込以前から新バージョンで動作中、のどれかに該当します。 |
| `stopped: ...` | 書込が停止したノードです。 |
| `not started` | 停止したノードの後続のノードです。 |

ノードが1台でも失敗した場合、コマンドはエラーで終了します。スクリプトは、バージョンが混在した書込結果を検出可能です。

DAGONの判定対象は、書込対象で応答のあるノードだけです。無応答のノードは判定せず、そのノードを理由にした復帰もありません。
`min_bootcore`は失敗後の判定対象外です。書込はノードのブートローダをアプリより先に配置し、ブートローダの失敗で停止します。新アプリが旧ブートローダ上で動作する状態は発生しません。
