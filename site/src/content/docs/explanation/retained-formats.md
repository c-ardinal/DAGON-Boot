この文書は[lifecycle-events.mdの5.5節](/explanation/lifecycle-events/#55-マイコンの識別とコンパイル済の構成-要件と実行可能なモデル)が実行可能なモデルに委任した形式の規範仕様です。対象はマイコンの識別とコンパイル済構成のノードのレイアウトです。ブートローダの試行のセル（5節）と状態ログの面と記録（6節）も規定します。ここにある形式は例外なく`crates/dagon-retained-model`が証明済のものです。形式の変更時は、最初にモデルを変更し、モデルのテストで決定します。

モデルはホスト専用で、リリースしません。各形式のコーデックはモデルのトレイトです（`BodyCodec`）。モデルのコーデックの証明はホスト上で実行します。設計上、ファームウェアのコーデックは同一のトレイトを実装し、同一のハーネスで試験します。

```
cargo test -p dagon-retained-model                       # 10^4 scenarios per world, fixed cases
cargo test -p dagon-retained-model --release -- --ignored # 10^6 scenarios per world
DAGON_MODEL_SCENARIOS=<n> DAGON_MODEL_SEED=<seed>         # override count and base seed
```

失敗したシナリオは、そのシード、構成、そして同一の性質でなお失敗する最小の一覧まで縮小した操作の一覧を表示します。そのケースを回帰テストとして`tests/fixed.rs`に追加します。

## 1. 故障モデル

証明がハードウェアについて仮定する内容と、注入する故障です。

- **ストア。** 保持メモリへの書込は、プログラム順にバイト単位のストアで実施します（1回の書込ステップの間にデータメモリバリアを挟んだvolatileのストア）。幅の広いストアは、異なる2個のステップのバイトを混在させない場合に使用可能です。32ビット単位だけのレジスタファイルは、ステップの隣接バイトを既存の値で再書込します。実行はどのバイトの後にも停止する場合があります（リセットか電断）。モデルは全書込の全バイトの後にこの停止を注入します。
- **リセット**は保持のバイトを残存させます。**電断**が残存させる対象は位置ごとに異なります（5）。
- **NORフラッシュ**は`0xFF`に消去し、ビットを1から0に書込します。中断された消去は、先頭の一部を消去済に、残存部分を旧値かランダムな値のままにします。中断された書込は、先頭の一部を書込済にします。どのバイトも（書込が中断されたコミットバイトも同様に）、次回の消去か書込まで、読出のたびに同一の値になります（弱いビットはありません）。一部だけ書込したバイトで異なる値を返却する場合があるフラッシュでは、マイコン定義のコードが、2回の読出の値が一致するまでコミットバイトを再読出する必要があります。
- **外来のバイト。** どのバイトも、その形式の書込側ではないもの（同一段階の別レイアウトの書込側や、故障）に上書きされる場合があります。モデルは全領域にランダムなバイトを注入します。

1個の保証は確率的です。ランダムなバイトが有効なエントリや記録として受理されるのは、8ビットのコミット値とCRC-32が偶然一致した場合だけです（スロットごとに最大2^-40）。以下のその他の保証は例外なく構造的なものです。確率ではなく、どの中断点でも成立します。

## 2. マイコンの識別

`identity(id)`は、`SHA-256("dagon-mcu/" ‖ id)`の最初の8バイトをリトルエンディアンのu64にした値です。`id`はマイコン定義の`id`です。識別を保持する箇所は、いずれも64ビット全部を保持します。識別を保持する箇所は`image-header`、`identity-reply`、`version-0x06`、`topology-node`です（モデルの`identity::CARRIERS`です。テストがこの行と照合します）。定義の読込は、いずれかの箇所の幅で識別が一致する2個の定義を、両方のidを提示して拒否し、その箇所の幅で全ビットがゼロか全ビットが1の識別を拒否します。読込したどの定義とも完全には一致しない識別のデバイスは、不明と表示します。数値のマイコンの表はありません。

## 3. コンパイル済の構成

### 3.1 本体（`topology-bin` 2）

先頭は16バイトです。マジック`DGTP`、レイアウトu16 LE（2）、ノード数（1から`MAX_NODES`）、リンク数（≤ `MAX_LINKS`）、制約数（≤ `MAX_CONSTRAINTS`）、ゼロ7バイトです。その後に以下の要素があります。

- ノードは各40バイト: 番号、役割、ポートの種類、試行の上限、待受時間ms u16 LE、マップのid、順番、復旧の段階[3]、ゼロ5バイト、オフセット16にマイコンの識別u64 LE、オフセット24にターゲットのタグ[16]。
- リンクは各20バイトで、イメージツールにおけるリンクのレイアウトです。向きはなく、2個の端それぞれにノード、ポートの番号、アドレスがあります。
- 制約は各16バイトで、マニフェストの制約のレイアウトです。

正規の形式: ノードの`index`は位置と同一、リンクの端はノードの順、リンクは端のノードの順、予約のバイトはゼロです。レイアウト1（16バイトのリンク）は読込しません。デコーダは再符号化して比較します。

## 5. ブートローダの試行のセル

stage0は待機中のブートローダの起動回数を、フラッシュではなく2個の保持のワードで計数します。この方式ではstage0にフラッシュの書込側がなく（stage0には書込しないので、保持するコードを最小限にします）、書込側の不具合が原因でstage0が何も起動しない状態になることはありません。`dagon_core::bootcore`がコーデックで、そのテストが証明です。

| マイコン | 位置 | 残存する対象 | 消失する対象 |
|---|---|---|---|
| RP2040 | ウォッチドッグのSCRATCH0、SCRATCH1（ブートROMはSCRATCH4-7を使用します） | 電源投入とRUNピン以外の全リセット | 電源 |
| STM32F401RE | RTCのバックアップレジスタBKP0R、BKP1R | ウォッチドッグによるリセットも対象とする全システムリセット | バックアップドメインの電源（VBATを接続している構成ではVDD） |

待機中のイメージ`p`の起動`n`（最大15）の値は、1個のワード`0xB7 << 24 | p.digest16[0] << 16 | p.digest16[1] << 8 | n << 4 | (!n &
0xF)`で、両方の位置にストアします。ワードが`p`の計数対象になるのは、タグ、ダイジェストのバイト、回数の検査（下位4ビットは回数の補数）が成立する場合だけです。セルは2個のワードのうち回数の最大値を計数し、`[0, 0]`はクリアされたセルです。ワードはそれぞれ1回のストアなので、リセットが2個のストアの間に発生する場合があります。その場合、新規ワード1個と旧ワード1個でも新規の起動を計数し、計数が減少することはありません。ランダムなワードが一致する確率は2^-28で、一致してもstage0がそのコアを早期に断念するだけです。

実行可能なモデルは`dagon-retained-model`の`world_trial`です。本番のコーデックと、stage0とブートローダの規則（`bootcore::choose`、`settle`）を、2個のワード上で実行します。新規コアを正常か破損として待機状態にし（破損したコアはstage0の検査に合格し、自身の検査に失敗します）、セルへのどのストアの後にも（セルの検査のストアも対象で、マイコンの順に、ワード0、次にワード1）、リセットか電断（セルはクリアかランダムになります）を挿入します。シードのシナリオを`cargo test`で実行し、完全なプロファイルではシナリオ数を大幅に増加して実行します。その性質を、全操作の後に確認します。

| Id | 性質 |
|---|---|
| C1 | 2回の電断の間に、待機中のコアを試行として起動するのは最大`max`回です。 |
| C2 | 追加の故障がなければ、最大`max + 1`回のブートで試行が終了します。待機中のコアはなく、あるコアが動作します。 |
| C3 | 破損したコアが確定することはありません。 |

マイコン定義のスイープ（`a_power_cut_at_every_flash_step_leaves_a_bootable_core`）は、フラッシュ側を追加します。書込の全フラッシュ操作での電断で、状態ログのコンパクションも対象です。

書込した値を一切保持しないセルは、起動したブートローダとアプリが実行する`bootcore::cell_holds`が検出します。そのようなノードはブートローダを受信せず、その状態を検出した待機中のコアは自身でロールバックします。

回数を保持するワードがあるセルは、stage0が書込したセルなので保持が成立しており、検査はそのセルに何も書込しません。何も計数していないセルにだけ、検査用の値（セルのワードが使用しない値）と検査前の値を、ワードごとに書込し、それぞれ再読出します。そのため、検査中のリセットで、セルが計数する起動が減少することはありません。

主張の限界: 各位置が、列挙したリセットをまたいで値を維持することは、ベンダーが文書で明示している動作です。

## 6. 状態ログの面と記録（`state-log` 1）

状態ログは、イメージのスロットの記録を収容します。この節は面と記録の規範です。面、面ヘッダ、スロットの記録の畳込は`dagon_format::statelog`と`dagon_core::log`の定義です。

ログは交互に使用する2面です。面は32バイトの面ヘッダと、後続の32バイトの記録で構成し、消去済のバイトは`0xFF`です。有効な面のうち世代が最大の面が使用中の面です。記録は順番に畳込し、畳込は最初の消去済記録か、最初のCRC不一致記録で終了します。

| オフセット | サイズ | 欄 |
|---|---|---|
| 0 | 1 | 種別: `0x01`から`0x7F`はスロットの記録、`0x80`から`0xFE`は予約、`0xFF`は消去済 |
| 1 | 3 | 種別ごとの欄 |
| 4 | 4 | `seq`: 連番、リトルエンディアン。畳込は連番を使用しません |
| 8 | 20 | 種別ごとの欄 |
| 28 | 4 | バイト0から27のCRC-32（ISO-HDLC） |

記録は、使用中の面にある最初の消去済記録へ、その32バイト全部の消去を確認した後に追記します。面が満杯の場合、面の末尾がCRC不一致記録の場合、この確認が不成立の場合、追記は事前にコンパクションを実行します。コンパクションは他方の面を消去し、畳込結果を複写し、世代に1を加算した面ヘッダを最後に記録します。その面ヘッダが完成するまで、旧面が有効です。読出側は、未知の種別の記録を無視します。
