## 仕様上の制限

- 署名の鍵をどう守るかは利用者が選びます。DAGONは決めません。ハードウェアの信頼の起点（セキュアブートのヒューズやハードウェアの鍵保管）を使うかどうかも、その選択です。
- マイコンの定義は、イメージの種類ごとにスロットを1つか2つ与えます（`[[slot]]`）。1つのスロットを読み込むのは、別の種類がそれを書き込むと`[writers]`が示すときだけです。スロットが1つの種類にできないことは次のとおりです。

| イメージの種類 | 前のバージョン | 書き込み中の電断 | 復旧するイメージ |
|---|---|---|---|
| `app` | 残りません。試行に通らない新しいバージョンにも戻る先がありません。`dagon rollback`は前のバージョンが無いと答え、DAGON Consoleはそのノードに戻す操作を出しません。 | スロットに起動できるアプリが残りません。 | アプリを書き込む別の種類（`[writers] app`）が起動し、アプリをもう一度受け取ります。ESP32-S3では、2nd stageが工場出荷の復旧用エージェントを起動します。 |
| `bootcore` | 残りません。試行に通らない新しいブートローダから、前のブートローダには戻れません。 | stage0が起動してよいブートローダが無くなり、状態ログの確定したAPPの記録が示すアプリを、確かめてから起動します。アプリの試行中は、アプリのエージェントがブートローダの転送とその待機の設定を断るので、この電断がアプリの試行と重なることはありません。 | その確定したアプリ（`[writers] bootcore`）が、ブートローダをもう一度書き込みます。確定したアプリが無いときだけ、stage0は何も起動せずにROMローダでの復旧を待ちます。 |
| `agent` | 残りません。 | 確定したアプリは動き続けます。復旧用エージェントは、もう一度書き込むまで使えません。 | 確定したアプリ（`[writers] agent`）が、もう一度書き込みます。 |
| `stage0` | 残りません。DAGONはstage0を現場で書き込みません。 | 現場で書き込まないので起きません。 | マイコンのROMローダ（`dagon flash`）。 |

- ブートローダは中継しません。書き込みモードか復旧モードでブートローダにとどまっているノードの先にしか届かないノードには、そのノードがアプリを動かしてから、また届きます。先にそのノードに書き込んでください。

## 今後解決する予定

親機とブート:

- リレー（`dagon-relay`）はマイコンに依存せず、リレーできるかどうかはマイコンの定義の`[coordinator]`で決まります。ノードはそのマイコンの定義の`[[relay_link]]`が並べるリンクで中継し、どのノードへどのリンクで届くかは構成が決めます。その定義と、リレーを動かすコードの両方を持つマイコンは、RP2040だけです。
- 書き込めるのは親機とその先の子機までです。子機より先の孫機には書き込めません。
- USBハブによっては、親機が自分に新しいバージョンを書き込んで再起動したあと、PCが親機を再び認識しないことがあります。親機はPCのUSBポートに直接つないでください。
- STM32F401のブートローダは通信しません。マイコンの定義はブートローダをアプリを書き込むもの（`[writers] app = ["app", "bootcore"]`）とし、待ち受けの時間（`[boot_receive]`）を与えますが、ブートローダのファームウェアは待ち受けの時間を開かず、書き込みモードも復旧モードも持たず、UPDATE_STAYを使いません。アプリはREBOOTのmode 1に`E_UNSUPPORTED`で答えます。このマイコンでスロットが1つのアプリは、書き込み中の電断のあと、もう一度書き込むものがありません。
- RP2040のブートローダが受け取るのはUSBだけです。マイコンの定義は`[boot_receive]`でI2CとUARTにも待ち受けの時間を与えますが、ブートローダはI2CとUARTのリンクを開かず、待ち受けの時間も開きません。アプリからの引き渡し（REBOOTのmode 1）と、起動できるものが無いときの復旧モードは、USBで受け取ります。USBの48MHzのクロックは水晶からしか作れないので、水晶の無いボード（リングオシレータ）のブートローダは何も受け取りません。そのボードでは、起動できるものが無いとき、ブートローダは止まり、表示灯があればそこに止まったことを示します。ESP32-S3の復旧用エージェントが受け取るのは、どのアプリのスロットも起動しないために2nd stageがそれを起動したときだけです。待ち受けの時間を開かず、HELLOには1や2ではなくmode 3で答えます。
- 組み込みのマイコンでstage0の検証にかかる最悪の時間を測った値は、記録していません。[stage0のクロックと検証の時間](/explanation/lifecycle-events/)にあるのはCortex-M0+のエミュレータによる見積もりで、STM32F401のCortex-M4の見積もりはありません。
- RP2040のブートには、水晶の無いボード（リングオシレータ、公称6.5MHz）でおよそ15秒、12MHzの水晶のあるボードでおよそ0.8秒かかります。stage0とブートローダが、毎回のブートで`Ed25519Small`による署名の検査をそれぞれ1回するからです。ブートローダは検査のあいだもウォッチドッグのキックを続けます。これは設計によるもので、小さい検証器でブートローダに書き込みのセッションの場所を残しています。
- RP2040のstage0、ブートローダ、アプリは、クロックを水晶かリングオシレータから取ります。XINに入れる外部クロックは取りません。
- ESP32-S3は公式のESP-IDFの2nd stageを使います。その2nd stage自体が壊れた場合、DAGONでは救えません。ベンダーのツールでUSBから書き直す必要があります。

拡張の隔離:

- ESP32-S3の隔離のレベルは`none`です。PMSとWCLのレジスタをプログラムするコードがありません。
- 実行時のサンドボックスはありません（Service ABI、Entry Gate、Operation Cancellation、Fault Unwind、Lockup Fuse、Reset Cleanup、SandboxArch）。定義の検査と保護マップの生成はあります。
- 保護マップを生成できる種類は`armv6m-mpu`と`armv7m-mpu`だけです。

リンク:

- ファームウェアがあるリンクの種類は`usb-cdc`、`uart`、`i2c`だけです。`ble`、`wifi-tcp`、`ethernet`、`can`にはありません。

識別とVERSION:

- マイコンの識別は手で割り当てた16ビットの`wire_id`です。イメージのヘッダ、識別の返答、VERSIONの0x06、構成のノードが持ちます。設計の、名前のハッシュから導く64ビットの識別ではありません。
- VERSIONが答えるのはid 0x01、0x06、0x0A、0x0B、0x0C、0x0Dだけです。空でないリクエストは拒みます。

署名の鍵:

- 署名の鍵はファイルからだけ読みます。環境変数`DAGON_SIGNING_KEY`が持つのもファイルのパスです。ほかの手段（環境変数、OSのキーストア、1Passwordなど）をポートで選ぶことはできません。

値とID:

- USBのVID:PID `c0de:cafe`は試験用のIDで、コードに固定されています。割り当てを受けたものではありません。
- DAGONのマイコンの定義には、`unverified`の印が付いた値があります。
- 実行モデルの上限（[12節](/explanation/lifecycle-events/#12-実行モデル)）は、12.3の決め方で決めた値ではありません。

設計の図にあってコードに無いコンポーネント:

- 置き換えのトレイトが無いポート: BuildRunner、Signer、DecisionPolicy、LogStorage、UpdateProtocol、Recovery、ImageVerifier、Digest、CryptoProvider、Diagnostics、Display、LogSink、Agent、Action
- 親機: Coordinator、Release Store、Bus Guardian。書き込みはPCが親機を通して進めます。
- 書き込みの計画: Delivery Planの試行の時間枠と昇格の判断
- 復旧: Recovery PolicyとNode Recoveryの、段階の自動の選択と回数に上限のある再試行
- ホスト: Host Machines、Host Extension Chain、Action Definitions
- ブート: Boot Record Writer、Boot Action Interpreter
- Retained Codecs: ブート記録とロックアップヒューズの形式は、実行可能なモデルの中にだけあります。ファームウェアにはありません。
- 構成の本体: ファームウェアの形式は`dagon-format`のもの（先頭32バイト、ノード32バイト）で、[保持と永続の形式](/explanation/retained-formats/)の形式ではありません。親機は1つの領域に保存し、2バンクの置き換えはありません。
