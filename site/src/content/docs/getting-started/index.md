## ブラウザで

[DAGON Consoleのデモ](~/demo/)はブラウザの内部で動作します。対象は模擬のPC接続ノード1つと、その接続先のノード2つです。

1. サンプルから構成を作成します。
2. 「書込」に切替後に「接続」をクリックします。
3. 「書込」をクリックすると、用意済の新規バージョンをノードへ書込します。

デモはファイルの読込と保存、機器への接続、キーの保持をしません。これらの操作部品をポイントすると、その理由を表示します。

## dagonコマンドで

`dagon`コマンドの[インストール](/getting-started/install/)を事前に実行します。

### `dagon sim`

```sh
dagon sim
```

シミュレータ上で一連のシナリオを実行します。

- 転送中に電断が発生する書込
- 未確定のイメージ
- 改ざんしたパッケージ
- 全消去したF401の、ROMブートローダ経由の復旧

`--topology`の指定で、独自の構成への書込を模擬します。各ノードはプロジェクトのMCU定義に準拠します。`--fault <ノードid>=<種類>`の指定で、指定ノードへ故障を注入します。

```sh
dagon sim --topology topology.yaml --fault seg=power-cut --fault hub=tamper
```

| 種類 | 対象ノードの状態 |
|---|---|
| `power-cut` | 書込中に電断が発生 |
| `no-confirm` | 新バージョンが未確定のまま |
| `tamper` | イメージの1ビットが反転 |
| `erased` | フラッシュを全消去し、ROMブートローダ経由で再書込 |

全ノードは1.0.0で開始し、模擬するリリースは1.1.0です。各故障は新規のシミュレーションで実行し、DAGONによるノード保護の成否を1行で表示します。シミュレータの対象は、PC接続ノードと、そこからI2CまたはUARTのリンク1本で接続するノードです。
